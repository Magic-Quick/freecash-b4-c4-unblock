## 1. Что нашлось при проверке (дефекты и несоответствия)

### 1.1 🔴 `2horizon_Red.png` не совпадает по геометрии с жёлтым набором

Габарит тела на одну ячейку у красного — **1.098** (213/2 × 97), у жёлтого `2horizon` — **1.024**
(211/2 × 103). Ячейка поля — **0.976** (`colPitch/rowPitch`, см. §3.1). Т.е. при посадке в ячейку
жёлтые сжимаются на 2–5%, а красный — на **12.5%**: главный блок рядом с соседним жёлтым будет
выглядеть заметно приземистее. Разница видна на глаз, это не допуск округления.

→ **Просить у дизайнера переэкспорт красного в габарите `2horizon.png` (241×133, тело 211×103).**
Не блокер: до правки живём с 12.5% сжатия (§4 Фаза A, шаг A3 — фолбэк).

### 1.2 🟡 Красный есть только как `2horizon`

Нет красного вертикального и красного len3. Это жёстко фиксирует дизайн: **главный блок обязан
навсегда остаться горизонтальным длины 2.** Для текущего L1 это правда, но любой новый уровень с
другим главным блоком упрётся в отсутствующий арт. Решение владельца требуется только если планируется
второй уровень (`GameConfig.levelsData` подписан «L1/L2», в `levels.json` уровень один).

### 1.3 🟡 Асимметричный паддинг у всех новых блоков

У каждого кадра прозрачное поле сверху 11 px, снизу 19 px (запечённая нижняя тень), по бокам ~15 px.
Если натянуть кадр на ноду ровно размером ячейки, тело блока окажется **меньше ячейки и смещено вверх
на ~3.5 design-units**. Текущий код (`BlockView.setup()`) ставит `contentSize` ровно = `length*pitch`,
т.е. с новым артом блоки не встанут вплотную к стенкам. Компенсация — §3.2.

### 1.4 🟡 Пэкшот-фон не совпадает по формату с канвасом

`bg.png` — 992×1586 (аспект 0.626), канвас — 720×1280 (0.563). Cover-fit в портрете даёт масштаб
**0.807** и обрезку ~10% по ширине (симметричный «коридор» — обрезка безопасна). В landscape тот же
cover даёт апскейл ×2.3 и обрезку ~65% по высоте — та же известная проблема, что и `OPEN_ISSUES #11`
для игрового фона. Не блокер, но landscape-пэкшот будет мыльным.

Решение: бг из новой папки не берем. Только визуал.

### 1.5 🔴 Вес: бюджет 5 MB уже превышен ДО новых ассетов

`GDD.md` §10 — «до 5 MB». Текущий однофайловый билд `build/plbx-html/unity/index.html` — **5.89 MB**.
Новая нарезка добавляет ещё **2.95 MB** сырого PNG. Без работы по весу пэкшот в билд не влезет —
подробный план в §5.

### 1.6 🟢 Мусор, который можно убрать заодно

- `assets/scripts/Systems/RewardSystem.ts.meta` — осиротевший `.meta` (самого `.ts` нет).
- `assets/prefabs/Block.prefab` хранит мёртвые сериализованные `tileFrame`/`mainFrame` — свойств с
  такими именами в `BlockView.ts` больше нет.
- `.DS_Store` в `assets/`, `assets/art/`, `assets/art/new assets/` — попадают в git.
- 9 ассетов с нулём ссылок из сцены/префабов (1.0 MB) — список в §5.2.

## 3. Целевая геометрия (посчитано, готово к применению)

### 3.1 Сетка поля (из `GameConfig`, не менять)

```
colPitch = (663-32)/6 * (640/755) = 89.148 design-units
rowPitch = (649-29)/6 * (600/679) = 91.311 design-units
аспект ячейки = 0.9763
```

### 3.2 Блоки: `contentSize` спрайта и смещение

Правило: **нода `Block` остаётся ровно размером ячейки** (`length*pitch × pitch`) — от неё зависят
хит-тест тапа и логика `resolveTapDirection`. Увеличивается и смещается **дочерняя нода `Visual`**,
чтобы её _тело_ (не raw-кадр) село ровно в ячейку.

Формула: `visualW = cellW * rawW / bodyW`, `visualH = cellH * rawH / bodyH`,
`offsetY = -(bodyCenterY - rawCenterY) * visualH / rawH`.

| Кадр           | Ячейка (w×h) | `Visual.contentSize` | `Visual.position` |
| -------------- | ------------ | -------------------- | ----------------- |
| `2horizon`     | 178.3 × 91.3 | **203.6 × 117.9**    | (0, −3.5)         |
| `3horizon`     | 267.4 × 91.3 | **296.5 × 117.9**    | (0, −3.5)         |
| `2Vertical`    | 89.1 × 182.6 | **117.6 × 208.8**    | (+0.5, −3.5)      |
| `3Verticl`     | 89.1 × 273.9 | **117.0 × 301.0**    | (0, −3.6)         |
| `2horizon_Red` | 178.3 × 91.3 | **204.2 × 120.5**    | (−0.4, −4.2)      |

Числа **не хардкодить в коде**: `BlockView` должен считать их из `SpriteFrame` + четырёх
`@property`-инсетов тела на кадр (или из общего инсета, если дизайнер выровняет паддинг по N1).

## 8. Как воспроизвести измерения

- Тела блоков: alpha-bbox по порогу `>200` (`PIL`), см. §0.1/§3.2.
- Позиции элементов пэкшота: template-match каждого PNG по `image.png` в окне ±40 px от центра,
  метрика — средняя абсолютная разница RGB по пикселям с `alpha>240`. Ошибка 0.00–0.79 → совпадение точное.
- Ссылки на ассеты: UUID из `.meta` → `grep` по `assets/scene.scene` и `assets/prefabs/**`.
